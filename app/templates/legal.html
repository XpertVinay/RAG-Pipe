04

Ingestion & Vector Embeddings Processing

When documents are submitted to a Room workspace, they undergo an automated ingestion lifecycle:

  1. Text Extraction & Sanitization: Raw text is extracted, stripped of harmful scripts or embedded macros, and split into chunks based on configurable size and overlap parameters (default 800 characters with 150-character overlap).
  2. Vector Generation: Each chunk is converted into a vector representation by your designated embedding model.
  3. Database Storage: Embeddings and chunk references are saved directly into the isolated ChromaDB vector store mapped to the specific Room ID and Organization ID.

No external service or unauthorized user can search or cross-reference your vector indices.

05

Dual-Tier Memory & Context Retention

Our architecture incorporates a two-tier memory system designed to provide context-aware responses without compromising privacy:

  • Short-Term Memory (STM): Transient conversational facts stored in ephemeral RAM cache, scoped strictly to the active session. STM items decay automatically when a session ends.
  • Long-Term Memory (LTM): Explicitly confirmed user preferences and enterprise domain facts stored in the database. LTM access is governed by strict RBAC (accessible only to authorized Staff and Admin accounts).
  • Transparent Control: Authorized users can view, prune, revaluate, or delete every individual memory fact in real time through the dedicated Memory Management Panel.
06

Multi-Tenant Isolation & Security Architecture

We implement comprehensive technical and organizational safeguards:

  • Encryption Standards: Data in transit is secured using modern TLS 1.3 protocol with strict cipher suites. Data at rest (SQLite databases, ChromaDB vector stores, uploaded files) is encrypted using industry-standard AES-256.
  • Strict Workspace Partitioning: Every room workspace maintains cryptographic isolation. Document queries enforce strict row-level security and room membership checks at the API middleware layer prior to vector search execution.
  • Sanitized Execution: Multi-agent autonomous code execution takes place in restricted sandboxes preventing unauthorized system calls, directory traversal, or network escalation.
07

Subprocessors & LLM Service Providers

To deliver multi-modal capabilities and secure payments, we engage selected sub-processors under rigorous data protection agreements:

  • Razorpay: Payment processing gateway for subscriptions and recurring billing. Razorpay is certified PCI-DSS Level 1 compliant. RAG Agent never receives, stores, or logs raw payment card credentials.
  • Cloud Foundation Providers (Optional): When configured by your administrator, queries may be dispatched to Google Cloud Platform (Gemini API), OpenAI Inc., or Anthropic PBC under enterprise zero-data retention agreements.
  • ChromaDB & SQLite: Localized vector and relational persistence engines operating within your designated environment boundaries.
08

Data Retention, Purge & Deletion Rights

We adhere strictly to the principle of data minimization:

  • Instant Self-Service Purge: You may at any time click the "Clear All Data" button in Settings to permanently delete all conversation transcripts, session histories, and contextual memory records.
  • Document Deletion: Deleting a file from the Document Library immediately unlinks the file, purges its vector embeddings from ChromaDB, and removes the physical file from the storage directory.
  • Account Termination: Upon account closure, all associated rooms, documents, embeddings, and credentials undergo complete cryptographic erasure within 30 days.

Autonomous AI Governance & Safety Framework

This policy defines the engineering guardrails, ethical boundaries, and human oversight controls governing our agent collaborative team, Model Context Protocol (MCP) tool executions, and retrieval-grounded generation.

01

Principles & Governance Scope

At RAG Agent, our mission is to empower teams with grounded, verifiable intelligence. Our AI architecture is governed by four fundamental pillars:

  1. Grounded Truth Over Hallucination: Models must justify assertions using verifiable citations from indexed documents. If source documents do not contain the answer, the model must explicitly state insufficient evidence.
  2. Human Agency & Oversight: Autonomous agents must never perform destructive actions without human confirmation.
  3. Zero Data Contamination: Proprietary context is ephemeral and isolated; it is never absorbed into public model weights.
  4. Transparent Tool Execution: Every step taken by autonomous agents—including search queries, script executions, and API calls—must be logged in the inspection audit trail.
02

The Agent Collaborative Architecture

Our multi-agent system orchestrates a cooperative team of specialized autonomous agents. Each agent operates under explicit behavioral constraints:

Agent Role Core Responsibility Safety Constraint & Guardrail
0. Decision Maker Evaluates user prompt intent, assesses query complexity, determines appropriate execution graph, and assigns sub-tasks. Enforces organizational scope; rejects prompts violating acceptable use.
1. Researcher Reformulates natural language queries into dense semantic search vectors to extract relevant document chunks from ChromaDB. Constrained strictly to documents present in the active room workspace.
2. Task Generator Deconstructs multi-step objectives into directed acyclic graphs (DAGs) of atomic, verifiable subtasks. Limits workflow recursion depth to prevent runaway computational cycles.
3. Task Executor Performs calculations, data transformations, and sandboxed script executions. Runs in sandboxed Python environments with no raw system privilege.
4. Validator Cross-references proposed responses against retrieved citation chunks, computing hallucination risk scores. Mandates citation anchors; rejects ungrounded extrapolations.
5. Deployer Synthesizes the validated answer, formats markdown and citations, and commits verified context to memory. Applies privacy filters to strip PII before writing to long-term memory.
03

Human-in-the-Loop (HITL) Controls

Autonomous execution is subject to human-in-the-loop safeguards:

  • Confirmation Gates: Actions that modify system state, overwrite stored files, or invoke external paid APIs require explicit confirmation via UI dialog prompts.
  • Emergency Stop Button: Users can abort running multi-agent workflows at any instant via the real-time cancellation control.
  • Audit Logs: Every reasoning step, tool invocation, and decision rationale is logged in the Workflow Inspector for post-execution review.
04

Model Context Protocol (MCP) & Tool Safety

When utilizing Model Context Protocol (MCP) tools for external integrations:

  • Least Privilege: MCP connectors are configured with minimal required scopes (e.g. read-only file access by default).
  • Payload Sanitization: All tool inputs and returned data undergo structural validation to mitigate indirect prompt injection attacks.
  • Execution Isolation: Script executions take place in isolated sandboxes with strict resource caps on memory, CPU, and execution timeout.
05

Grounding & Hallucination Prevention

We mandate strict grounding standards across all generation pipelines:

  • Source Attribution: Responses must explicitly link statements to specific document chunk IDs. Users can click any citation pill to inspect the verbatim source text.
  • Insufficient Evidence Protocol: If the retrieved document context does not contain sufficient factual evidence to substantiate an answer, the model is strictly prompted to declare: "The indexed documents do not provide sufficient information to answer this query."
06

Dual-Tier Memory Ethical Rules

Our two-tier memory system operates under transparent governance:

  • Automated PII Scrubbing: Personal identifiers (e.g., social security numbers, credit card numbers, personal health identifiers) are automatically redacted before facts are committed to Long-Term Memory.
  • Memory Inspection & Purge: Organization members can view, edit, or delete any extracted memory fact at any time in the Memory Tab.
  • No Cross-Tenant Sharing: Memory items are strictly scoped to the tenant organization and are never shared across organization boundaries.
07

Strictly Prohibited AI Use Cases

The following activities are strictly prohibited when using RAG Agent:

  • Developing autonomous cyber weapons, malware, or vulnerability exploitation frameworks.
  • Deploying models for fully automated legal sentencing, high-stakes medical diagnosis, or credit worthiness decisions without human oversight.
  • Generating non-consensual deepfakes, synthetic CSAM, or targeted harassment materials.
  • Conducting biometric mass surveillance or facial identification harvesting.
08

Users are always informed which foundation model is executing their query (e.g., Ollama Qwen2.5, Google Gemini, OpenAI GPT-4o, or Anthropic Claude). The active model is permanently displayed in the navigation header badge. Detailed telemetry—including token consumption, latency, and step logs—is provided in real time to ensure total transparency.
